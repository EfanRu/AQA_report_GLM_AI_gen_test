# TestReport — отчёты по автотестам

Сервис отчётности по автотестам для закрытого контура: перезапуски, комментарии о причинах падений, отчёты по версии билда, сравнение прогонов и дельта-загрузка. Заменяет собой то, чего не хватает Allure: [архитектура](docs/testreport-architecture.md).

## Быстрый старт (демо)

Требования: Node 18+, Docker.

```bash
npm install                # воркспейсы: app (Next.js) + generator
docker compose -f deploy/docker-compose.yml up -d postgres
npm run db:push            # создать схему testreport в БД
npm run demo               # сгенерировать демо-данные (3 билда, ~11k результатов)
npm run dev                # http://localhost:3000
```

## Что смотреть в демо

Демо-данные — 3 билда (генерируются детерминированно):

| Билд | Сценарий |
|---|---|
| **2.9.0** (по умолчанию) | прогон CI **оборван на 62%**, ещё идёт: бейдж «выполняется», группы причин, «без комментария: N» |
| **2.8.0** | полный CI-прогон + **локальный реран** Дмитрия: счётчик «Починен 110», 9 групп причин по категориям |
| **2.7.0** | полный CI-прогон + CI-реран (~55% починено) |

Сценарий показа:

1. **Билд 2.9.0** → кнопка «Отсутствуют…» у прогона #5: 1120 тестов нет относительно полного прогона #3; кнопки копирования списка (`Class.method` и `-Dtest=…`) для перезапуска.
2. В другом терминале `npm run demo:progress` — листенер «дописал» ещё 400 результатов. В UI нажмите **Обновить** — придёт только дельта (видно в шапке: «догружено +N»).
3. Переключитесь на **2.8.0**: «Починен 110» (тест упал в CI, починился в локальном реране), клик по группе причин — фильтр таблицы; клик по тесту — карточка с попытками, ошибками и stack trace.
4. Поставьте имя в шапке → выделите чекбоксами упавшие без комментария → панель внизу — массовый комментарий (категория + текст). Группа «Без комментария» в сводке уменьшится.
5. Фильтры: клики по счётчикам/чипам статусов, поиск по классу/методу, поиск по тексту ошибки, теги.

## Скрипты

| Команда | Что делает |
|---|---|
| `npm run dev` | Next.js dev-сервер на :3000 |
| `npm run build` / `npm start` | prod-сборка / запуск (standalone) |
| `npm run typecheck` | tsc --noEmit по app |
| `npm run db:push` | применить drizzle-схему к БД |
| `npm run demo` | пересоздать демо-данные (truncate + генерация) |
| `npm run demo:progress` | дописать 400 результатов в незавершённый прогон (имитация живого листенера) |

## Архитектура в двух словах

- **Писатели** — Java-листенер автотестов (CI и локальные запуски) вставляет `runs`/`results`/`test_defs` напрямую в Postgres (INSERT-only, идемпотентно по `ci_run_id`).
- **Сервис** (Next.js: UI + API в одном деплойменте) — только читает результаты и пишет `failure_comments`. Результаты immutable: статус «починен» вычисляется при чтении (последняя попытка выигрывает).
- **Дельта-загрузка** — срез билда кешируется в браузере с курсором `maxResultId`; обновление тянет только строки с большим id. Полная загрузка — по кнопке.
- **Отсутствующие тесты** — обрыв пайпа виден как незавершённый прогон; `/api/missing` сравнивает его с последним полным прогоном (авто-выбор по максимальному покрытию) и отдаёт список для перезапуска.
